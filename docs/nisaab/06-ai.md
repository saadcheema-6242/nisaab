LangGraph agent · 28 tools · Gemini on Vertex AI

This is where NISAAB stops being a CRUD app. The design question throughout was not
"how do we call an LLM" but **"how do we stop it inventing a syllabus?"**

---

## The agent

Built with LangChain's `create_agent`, in `src/shared/ai/src/edu_ai/chatbot/factory.py`:

```python
return create_agent(
    model=llm,
    tools=[*rag_tools, *syllabus_tools, *web_tools, *practice_tools,
           *flashcard_tools, *quiz_tools, *note_tools, *mind_map_tools],
    middleware=[
        capture_sources_from_rag,
        dynamic_system_prompt,
        ensure_sources_in_stream,
    ],
    state_schema=ChatbotState,
    context_schema=ChatbotContext,
)
```

### Three middleware, three jobs

| Middleware | Hook | Does |
|---|---|---|
| `capture_sources_from_rag` | `@wrap_tool_call` | Intercepts document searches and records which segments were used, so the answer can cite them |
| `dynamic_system_prompt` | `@dynamic_prompt` | Builds the system prompt **per request** from the student's class, group, language and the SLO in scope — then caches it by that key |
| `ensure_sources_in_stream` | `@after_model` | Carries the captured sources into the streamed update so the browser can show them beside the answer |

The prompt is dynamic because a Class XI Pre-Medical student asking in Roman Urdu and a
Class XII Pre-Engineering student asking in English should not get the same instructions.
Caching on `(language, fbise context)` keeps that from costing anything.

### The `_scoped` pattern

Every creation tool comes in two forms. `create_quiz` takes a topic in words.
**`create_quiz_scoped` takes an SLO code** — and generates against that outcome's real
text, cognitive level and assessment form.

That pairing is the heart of the project. The scoped tool is what makes the output
*Federal Board* content rather than plausible-looking content.

### `return_direct` — knowing when to stop talking

The five practice tools are marked `return_direct=True`, so they **end the tutor's turn
immediately**.

The reason is a small thing that matters a lot: when a student asks for a flashcard, the
card *is* the answer. A model that produces the card and then adds "Here is your
flashcard! Let me know if you'd like another!" has buried the thing they asked for. The
tool returns, the turn ends, the card appears.

## Grounding: how an SLO reaches the prompt

`agents/slo_context.py` loads one SLO and everything that gives it meaning:

```python
class SloContext(BaseModel):
    code: str
    description: str
    domain: str
    content_area: str | None
    assessment_form: str        # summative | formative | practical
    cognitive_levels: list[str] # K, U, A
    subject: str
    grade_label: str            # "Class XI (HSSC-I)"
```

The cognitive level is not decoration — it is handed to the model as an instruction:

| Code | Expanded in the prompt as |
|---|---|
| `K` | Knowledge |
| `U` | Understanding |
| `A` | Application |

So a question generated for an **A**-level SLO is asked to require applying the idea to
a new situation, not reciting it. That is the difference between a question that looks
like a board question and one that *is* one.

### Language

Three options, and the prompt describes each precisely rather than by name alone:

```python
LANGUAGE_NAMES = {
    "en": "English",
    "ur": "Urdu (in Urdu script)",
    "ur-Latn": "Roman Urdu (Urdu written in English letters, as Pakistani students text)",
}
```

That last description exists because "Roman Urdu" alone produced stilted transliteration.
Telling the model *how Pakistani students actually text* produced something students
recognise.

## Models and the fallback chain

Gemini through Vertex AI's OpenAI-compatible endpoint
(`GeminiChatOpenAI extends ChatOpenAI`), so the whole LangChain ecosystem works unchanged.

### Four roles, separately configurable

| Role | Used for | Current model |
|---|---|---|
| `TUTOR` | Chat | `gemini-3.5-flash` |
| `GENERATION` | Quizzes, papers, notes, maps | `gemini-3.5-flash` |
| `MARKING` | Marking written answers | `gemini-3.5-flash` |
| `OCR` | Reading scanned uploads | `gemini-3.5-flash` |
| *embeddings* | RAG | `gemini-embedding-001` |

They point at the same model today, but each is a separate setting — marking could move
to a stronger model without touching chat.

### Falling back

```
gemini-3.5-flash  ──►  gemini-3.5-flash-lite  ──►  gemini-2.5-flash
```

Only these errors advance the chain:

```python
FALLBACK_ERRORS = (
    openai.RateLimitError,
    openai.InternalServerError,
    openai.APIConnectionError,
    openai.APITimeoutError,
)
RETRIES_BEFORE_FALLBACK = 2
```

A **bad request is not retried** — only transient failures are. A capacity problem at
Vertex degrades the model rather than failing the student's request.

### Two settings bought with real downtime

```python
llm_max_retries: int = 3        # was 8
llm_request_timeout: float = 90.0   # did not exist
```

A practice paper once ran for **over nine minutes** before anyone noticed why: there was
**no timeout on the LLM call at all**. A stalled connection simply never returned, and
eight retries per model across a three-model chain multiplied every slow call. Adding
the timeout and cutting retries took a half board paper to **38 seconds**.

## Making the model behave: three fixes worth recording

Prompt engineering alone did not solve any of these. Each needed code.

### 1 · "Board level" meant difficulty, not length

Asking for a "board level" paper produced a 14-mark mini paper. The model had read
*level* as *size*. Fixed by rewriting the tool descriptions so length and difficulty are
plainly separate choices.

### 2 · The same question, twice

The tutor kept re-asking what scope the student wanted, having already been told. A
prompt instruction not to was unreliable, so the filter became code — `SCOPE_WORDS` and
`_asks_about_scope()` detect a redundant scope question and drop it.

### 3 · Asking for a chapter it had already been given

Say "complex numbers" and the tutor would still ask which chapter, because matching was
against domain names only and "complex numbers" is a sub-topic. Now it falls back to
searching the SLOs themselves:

```python
named = wanted not in ("", WHOLE_SYLLABUS.lower(), "all", "everything")
if match or (named and slo_choices(grade_subject_id, topic, limit=3)):
    return None   # they told us; stop asking
```

**The lesson in all three: when the model must behave a certain way, enforce it in code.
A prompt is a request, not a guarantee.**
